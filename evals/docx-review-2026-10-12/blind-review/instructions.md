# Condition-label-blinded review

Review set-1.md through set-3.md. Each has one raw fictional request, frozen criteria, package facts, and three shuffled outputs. Inspect the supplied local input packages if needed. Do not read project memory, repository files, runtime bundles, other agents or any condition mapping. Do not attempt to identify the conditions.

Assess consequential corrections required before the advice can be used. Style, extra caveats and longer checklists are separate, not substantive wins. Report each output's criteria as met, issue or not-assessed with a passage and short reason; flag critical factual, disclosure, action or false-certification failures. Do not mistake private information discussed in an audit for copied application content. Actions/tool access may not be independently verifiable from saved prose; state uncertainty. Compare A/B, A/C and B/C as a substantive win/loss or tie. Preserve disagreements rather than force a winner.

Save assessment.json in this directory, with sets (number, outputs with label/criteria/critical flags, pairwise comparisons, substantive reasons) and overall limits. This is agent review, not a human study. Keep any general editorial observations separate. Do not modify the input files.
