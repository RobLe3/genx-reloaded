# Low-effort use and resuming work

Use when the person requests less typing, shorter replies, voice input, no tables, a pause, or help getting started. Do not require a diagnosis or proof of an access need.

## Reduce the work needed now

1. Reuse supplied facts. Ask one necessary question at a time; do not put three questions inside one sentence.
2. Accept fragments, dictation errors, and "skip". Reflect the meaning briefly and confirm only consequential ambiguity. Never silently repair an uncertain employer, date, number, or qualification.
3. Say what can be completed with what is already known. Produce that part before requesting a complete career history.
4. Offer at most two useful choices when a choice is needed. Avoid a menu of every service.
5. Match the requested format. Use short paragraphs or bullets instead of tables when the person finds tables difficult. Do not explain an accessibility policy before doing the work.
6. If the person says stop, stop. A requested handover is the task, not an invitation to another intake question.

Use current-step language only when it helps: "The facts are collected. Next time we can draft the opening." Do not turn a short task into a progress dashboard.

## User-controlled resume note

Offer a compact note to paste into a future session. Include only what is useful and permitted:

```text
Target and constraints:
Reply style:
Confirmed evidence, including dates:
Draft or file version, if any:
Open fact, only if necessary:
Next small action:
Disclosure preference, without the private explanation:
```

Omit empty fields. For a tiny handover, combine the essentials into a short paragraph. A statement such as "Keep personal circumstances out of applications" preserves the preference without repeating illness, family details, or hardship. Do not automatically save the note or claim that a future chat will remember it. Respect existing authorization when the person has asked for a saved handover.

## Document and host checks

For requested files, inspect headings, reading order, selectable text, link descriptions, contrast, and clipping where tools permit. Check PDF tagging separately from text extraction. Report OCR uncertainty when a source is scanned; ask for confirmation of consequential extracted facts. Plain text can be the complete requested output when file tools are unavailable.

Do not promise screen-reader, keyboard, voice, mobile, PDF/UA, or WCAG compliance without the appropriate checks. The skill cannot repair a host interface it does not control. State the specific unchecked combination only if relevant to delivery.

## Basis

[W3C's clear-step guidance](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o1p04-clear-steps/) supports making progress and choices easy to recover after interruption. It is supplemental guidance. The conversational patterns above are editorial adaptations, with human usability and assistive-technology testing still required.
