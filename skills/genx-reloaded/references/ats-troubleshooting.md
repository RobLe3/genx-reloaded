# ATS troubleshooting across surfaces

Checked 12 October 2026. Offer a manageable repair, not a catalogue of everything that could go wrong. These are documentation-based diagnostic steps, not proven hiring interventions. No live employer ATS has been tested.

## Establish what actually happened

Reuse supplied facts. Ask for only the missing detail that changes the next action: exact error, application stage, job reference, file type/size, or a redacted screenshot. Do not request passwords, session links, government identifiers, private referee data, or a full CV to solve a login error.

Record separately: target country; employer and vacancy; visible application surface; evidenced ATS/product; optional parser or assessment provider; observed symptom; submission state. Mark vendor identity as confirmed by the page/help notice, candidate-reported, tentative, or unknown. Branding and familiar URL patterns are clues, not proof of enabled features or legitimacy. Use the employer's verified careers link; do not probe private endpoints or infer backend settings.

Read the matching country and vendor card when relevant. Recheck current official instructions before relying on numeric file limits, update/withdrawal behaviour, AI notices or legal routes. If browsing is unavailable, label the cached guidance with its checked date and keep the next action reversible.

## Match the symptom to the layer

| Observed problem | Check next | Practical response |
| --- | --- | --- |
| Cannot upload | Actual field's allowed types/size, password protection, error text | Save an accepted text-based copy; preserve the original; inspect local extraction and appearance |
| Upload accepted, fields wrong/empty | Name, contact, employers, titles, dates and education in the actual form | Correct editable fields; a blank custom field may be a product limitation, not a bad CV |
| Old resume or cover letter returns | Job-board saved files, reused profile, previous application | Select the intended version at the originating surface; compare attachment and form before submission |
| No completion receipt | Draft/profile versus job-specific submission, outstanding tasks, confirmation page | Check status before retrying; a talent-community signup is not necessarily an application |
| Fast rejection | Exact screening questions and truthful answers, explicit feedback | Identify possible qualification/rule issues without asserting the cause from timing |
| Low score or match category | Which product/feature produced it and what criteria are actually known | Make supported evidence explicit; an external checker cannot reveal a hidden employer threshold |
| Need to correct submitted data | Application state and vendor's current update guidance | Prefer correction/support options; withdrawal can cancel assessments or prevent reapplication |
| Login or inaccessible interface | Correct employer portal, official recovery/support, saved draft | Preserve work first; offer an accessible alternative request; do not repeatedly create accounts |

Stop after one or two targeted attempts if the same failure persists, especially near a deadline. Save the error and timestamp privately and draft a short request for help or an alternative submission route. Never promise an extension, successful submission or human review.

## Surface is not system

An employer site can embed an ATS form; a job board can transmit an application; an agency, referral or email can create an ATS record. None guarantees bypassing screening. LinkedIn/Indeed/SEEK, a candidate portal, an assessment link and the employer's system may each hold different data. Follow the actual observed route; do not apply a LinkedIn-specific fix to Indeed or assume a profile change propagates to previously submitted applications. Never send duplicate applications merely to test which route scores better.

## Evidence from different origins

Use candidate-visible errors for the actual symptom, official vendor documentation for feature behaviour, employer instructions for configuration and eligibility, regulators/statutes for jurisdictional rights, and original studies for bias findings. Community reports can suggest a question but cannot establish prevalence or a hidden ranking rule. Vendor fairness claims are not independent validation. A disclosed feature does not establish why this person was rejected.

Do not invent a universal ATS score, keyword density, file rule, age filter or opt-out. Do not suppress the possibility of screening automation when documented. Never use hidden text, prompt injection, false eligibility answers, fake experience, identity changes, or account rotation as a remedy. Keep required chronology truthful and retain relevant older evidence.

## Deliver one useful next step

Give: **what we observed; what is documented; what remains unknown; the smallest repair; how to check it; the next contact if it fails.** Keep it short for a tired candidate.

Optional private issue note: job reference, country, surface/vendor and confidence, source URL/check date, exact redacted error, file version, action tried, result, deadline and next step. Save only when wanted and permitted; never put real candidate notes into the reusable skill.

Draft-only support message: 'For [job reference], I reached [step] at [time/time zone] and saw [error]. I tried [action]. Could you confirm whether my application was received and advise how to correct [field/file] without losing my place or assessment invitation?' Replace brackets with known facts or omit them before sending. Do not contact anyone without authorization.
